# Сайт семейного психолога Галины Курановой

Небольшой сайт частной психологической практики: основная страница с описанием услуг и формой записи, а также отдельная страница «Обо мне». Проект сделан на чистых HTML, CSS и JavaScript — без фреймворков, сборки и зависимостей для фронтенда.

Заявки из формы отправляются в Telegram через Cloudflare Worker. Так токен Telegram-бота остаётся на сервере и не попадает в исходный код страницы.

## Возможности

- Главная страница с представлением специалиста, запросами клиентов, принципами работы, услугами, стоимостью и контактами.
- Отдельная страница «Обо мне» с историей, образованием и описанием подхода.
- Адаптивная вёрстка для телефонов, планшетов и компьютеров.
- Якорная навигация по основным разделам и заметная кнопка записи.
- Клиентская проверка обязательных полей и согласия на обработку данных.
- Понятные сообщения об успешной отправке или ошибке прямо под формой, без `alert()`.
- Блокировка кнопки на время запроса, чтобы не отправить одну заявку несколько раз.
- Плавное появление секций при прокрутке с учётом настройки `prefers-reduced-motion`.
- Серверная проверка данных и экранирование HTML перед отправкой в Telegram.
- Базовые SEO-настройки: заголовки, описания, Open Graph и семантическая HTML-разметка.
- Автоматическое обновление года в подвале сайта.

## Технологии

- **HTML5** — структура и содержимое страниц.
- **CSS3** — оформление, Grid/Flexbox, CSS-переменные и адаптивность.
- **Vanilla JavaScript** — валидация формы, отправка запроса, анимации и текущий год.
- **Cloudflare Workers** — серверная обработка заявок.
- **Telegram Bot API** — доставка заявок специалисту.
- **Google Fonts** — шрифт Cormorant Garamond для заголовков с системными fallback-шрифтами.

Для просмотра и редактирования сайта не нужны Node.js, npm, бандлер или база данных. Node.js и Wrangler понадобятся только для локального запуска и публикации Cloudflare Worker.

## Запуск локально

### Самый простой способ

Откройте `index.html` двойным щелчком в браузере. Все основные страницы и стили будут работать без дополнительных действий.

Форма при этом не сможет отправить заявку, пока не настроен Cloudflare Worker. Это ожидаемое поведение: сайт покажет сообщение об ошибке и предложит связаться через Telegram.

### Через локальный HTTP-сервер

Такой вариант ближе к работе сайта на хостинге.

1. Клонируйте репозиторий:

   ```bash
   git clone https://github.com/galikura/family-therapy-site.git
   cd family-therapy-site
   ```

2. Запустите сервер из корня проекта.

   В Windows с установленным Python:

   ```bash
   py -m http.server 8000
   ```

   В macOS или Linux:

   ```bash
   python3 -m http.server 8000
   ```

3. Откройте [http://localhost:8000](http://localhost:8000).

Останавливается локальный сервер сочетанием `Ctrl+C`.

## Разделы сайта

Главная страница `index.html` содержит:

- `#hero` — имя, специализация, краткое описание подхода, фотография и кнопка записи.
- `#benefits` — ситуации, с которыми можно обратиться.
- `#trust` — образование, принципы работы и отзывы.
- `#services` — форматы консультаций, длительность и стоимость.
- `#form` — форма записи на первую консультацию.
- `#contacts` — адрес и форматы работы, способы связи, политика конфиденциальности.

Страница `about.html` раскрывает профессиональную историю и подход к работе. Она использует общий файл `css/style.css` и ту же фотографию из `img/photo.jpg`.

## Как редактировать содержимое

Основные тексты находятся непосредственно в `index.html` и `about.html`. Места, предназначенные для замены, отмечены комментариями:

```html
<!-- ЗАМЕНИТЬ: ... -->
```

Найдите слово `ЗАМЕНИТЬ` через поиск редактора и последовательно проверьте все такие места. Обычно достаточно менять текст между HTML-тегами, сохраняя саму разметку.

Подробная инструкция для редактирования без технического опыта находится в файле [КАК-РЕДАКТИРОВАТЬ.md](./КАК-РЕДАКТИРОВАТЬ.md).

### Тексты и контакты

Перед публикацией рабочей версии сайта проверьте:

- имя, специализацию и сведения об опыте;
- образование и используемые методы;
- описания услуг, длительность встреч и стоимость;
- город, телефон, Telegram и адрес электронной почты;
- срок ответа на заявку;
- текст политики конфиденциальности.

Отзывы, изначально добавленные как демонстрационные заглушки, нужно заменить на реальные отзывы, опубликованные с согласия клиентов, либо убрать. Не следует выдавать примеры текста за реальные отзывы или подтверждённые результаты работы.

### Фотография

Текущее фото хранится в `img/photo.jpg`. Самый простой способ замены — сохранить новое изображение под тем же именем. Тогда HTML менять не потребуется.

При использовании другого имени или формата обновите `src` в обоих HTML-файлах и сохраните содержательный атрибут `alt`. Для быстрой загрузки желательно заранее уменьшить изображение и использовать JPG или WebP.

### Цвета и оформление

Основные цвета, шрифты, ширина контейнера, радиусы и тени заданы переменными в начале `css/style.css`:

```css
:root {
  --color-bg: #FAF6F1;
  --color-primary: #7A8B6F;
  --color-accent: #C48A6A;
  --container: 1100px;
}
```

Изменение этих переменных позволяет скорректировать оформление без правки каждого компонента отдельно.

## Как работает форма заявки

Форма содержит три текстовых поля: имя, способ связи и необязательное описание запроса. Отдельный обязательный флажок подтверждает согласие на обработку персональных данных.

После нажатия кнопки:

1. JavaScript проверяет обязательные поля и согласие.
2. При ошибке сообщение появляется рядом с соответствующим полем.
3. Если данные заполнены, кнопка блокируется, а браузер отправляет JSON-запрос на адрес из `FORM_ENDPOINT`.
4. Cloudflare Worker повторно проверяет данные и ограничивает длину полей 500 символами.
5. Worker экранирует HTML и передаёт заявку в Telegram Bot API.
6. Пользователь видит результат отправки в элементе с `aria-live="polite"`.

Прямой вызов Telegram Bot API из браузера намеренно не используется: он раскрыл бы токен бота каждому посетителю сайта.

## Настройка Cloudflare Worker и Telegram

Краткая последовательность приведена ниже. Более подробная инструкция с получением токена и `chat_id` находится в [server/README.md](./server/README.md).

### 1. Подготовьте Telegram-бота

Создайте бота через `@BotFather`, получите токен и узнайте `chat_id` чата, в который должны приходить заявки.

Токен и `chat_id` не добавляйте в HTML, JavaScript, Git или публичный `README.md`.

### 2. Установите Wrangler

```bash
npm install -g wrangler
wrangler login
cd server
```

### 3. Создайте конфигурацию Worker

Создайте файл `server/wrangler.toml`:

```toml
name = "therapy-form"
main = "worker.js"
compatibility_date = "2025-01-01"
```

Имя Worker при необходимости можно изменить.

### 4. Сохраните секреты в Cloudflare

Команды выполняются из каталога `server`:

```bash
wrangler secret put TELEGRAM_BOT_TOKEN
wrangler secret put TELEGRAM_CHAT_ID
```

Wrangler запросит значения интерактивно. В коде остаются только обращения к `env.TELEGRAM_BOT_TOKEN` и `env.TELEGRAM_CHAT_ID`.

### 5. Опубликуйте Worker

```bash
wrangler deploy
```

После публикации Cloudflare покажет URL вида:

```text
https://therapy-form.ваш-поддомен.workers.dev
```

### 6. Подключите Worker к сайту

В начале `js/script.js` замените значение `FORM_ENDPOINT`:

```js
const FORM_ENDPOINT = "https://therapy-form.ваш-поддомен.workers.dev";
```

В `server/worker.js` укажите точный домен сайта:

```js
const ALLOWED_ORIGIN = "https://www.example.ru";
```

Значение `ALLOWED_ORIGIN` должно содержать схему и домен без пути и завершающего `/`. После изменения Worker нужно опубликовать повторно командой `wrangler deploy`.

### Локальная проверка Worker

```bash
cd server
wrangler dev
```

По умолчанию Worker будет доступен на `http://localhost:8787`. Для локального теста временно укажите этот адрес в `FORM_ENDPOINT` и разрешите нужный источник в CORS. Перед публикацией верните боевой домен; не оставляйте `ALLOWED_ORIGIN = "*"` в рабочей версии.

## Публикация статической части

Сайт можно разместить на любом статическом хостинге. Сборка не требуется.

### Netlify

1. Создайте новый сайт через импорт из GitHub и выберите репозиторий.
2. Оставьте команду сборки пустой.
3. Укажите корень репозитория (`.`) как каталог публикации.
4. Запустите деплой и проверьте обе HTML-страницы.

Для работы формы домен Netlify должен совпадать с `ALLOWED_ORIGIN` в Worker.

### Cloudflare Pages

1. Подключите GitHub-репозиторий к новому Pages-проекту.
2. Не выбирайте фреймворк и не указывайте команду сборки.
3. Используйте корень репозитория как каталог готового сайта.
4. После деплоя настройте домен в `ALLOWED_ORIGIN` и обновите Worker.

Cloudflare Worker публикуется отдельно от статических файлов.

## Доступность и SEO

В проекте уже предусмотрены:

- русский язык документа через `lang="ru"`;
- семантические элементы `header`, `main`, `section`, `footer` и `nav`;
- один основной заголовок `h1` на каждой странице;
- подписи `label` у полей формы;
- видимая клавиатурная фокусировка через `:focus-visible`;
- сообщения формы, доступные скринридерам;
- отключение анимаций при системной настройке уменьшения движения;
- `title`, `meta description` и основные Open Graph-теги;
- адаптивные изображения и альтернативный текст.

После изменения текстов метаописания и Open Graph также следует актуализировать.

## Безопасность

- Не вставляйте токен Telegram-бота в браузерный JavaScript.
- Храните `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` только в секретах Cloudflare.
- Файл `.dev.vars` с локальными секретами исключён через `.gitignore`.
- Ограничивайте CORS реальным доменом сайта вместо `*` в production.
- Сохраняйте серверную валидацию даже при наличии проверки в браузере.
- Не отправляйте через форму и не записывайте в код данные, которые не нужны для ответа на заявку.

## Проверка изменений

Автоматических тестов в проекте нет. Синтаксис JavaScript можно проверить командами из корня репозитория:

```bash
node --check js/script.js
node --check server/worker.js
```

После правок также вручную проверьте:

- главную страницу и страницу «Обо мне»;
- все навигационные ссылки и якоря;
- отображение на узком мобильном экране и на десктопе;
- пустую, неправильно заполненную и корректную форму;
- состояния успешной отправки и ошибки;
- отсутствие повторной отправки во время запроса;
- отсутствие ошибок в консоли браузера;
- навигацию с клавиатуры и режим уменьшенного движения.

## Чеклист перед рабочим запуском

- Заменён телефон-заглушка `+7 (000) 000-00-00`.
- Проверены контакты, факты, цены, форматы и профессиональные сведения.
- Демонстрационные отзывы заменены на разрешённые реальные отзывы или удалены.
- Политика конфиденциальности приведена в соответствие с реальной обработкой данных.
- Настроен `FORM_ENDPOINT` в `js/script.js`.
- Настроен `ALLOWED_ORIGIN` в `server/worker.js`.
- Секреты Telegram сохранены через Wrangler и отсутствуют в Git.
- Отправка заявки проверена на опубликованном домене.
- Проверены мобильная версия, ссылки, метаописания и текст ошибок.
