# Техническая документация: Сайт-визитка семейного психолога

> Документ предназначен для ИИ-агента, реализующего проект. Следовать спецификации точно; отклонения — только по явному запросу заказчика.

---

## 1. Обзор проекта

Одностраничный сайт-визитка (landing page) частного семейного психолога.
Цель сайта — познакомить посетителя со специалистом, снять возражения и получить заявку через форму обратной связи.

- **Язык контента:** русский
- **Тексты:** правдоподобные заглушки (агент пишет их сам в спокойной, профессиональной манере психолога). Заказчик подставит свои тексты и фото позже — поэтому весь контент должен быть легко заменяем.
- **Целевая аудитория:** семейные пары и родители, 25–50 лет, рассматривающие терапию.

---

## 2. Стек и ограничения

**Максимально простой стек — без сборки, без зависимостей:**

- HTML5 (семантическая разметка)
- CSS3 (один файл, кастомные CSS-переменные, flex/grid; БЕЗ фреймворков)
- Vanilla JavaScript (один файл; только валидация формы и отправка заявки)
- Один крошечный серверный скрипт для проксирования заявки в Telegram Bot API (см. §6)

**Категорически запрещено:** React/Vue/другие фреймворки, Tailwind, jQuery, npm-зависимости, бандлеры, препроцессоры, иконочные шрифты. Иконки — только инлайн-SVG при необходимости.

**Шрифты:** системный стек или один Google Font семейства serif для заголовков (например, `Playfair Display` или `Cormorant Garamond`) + системный sans-serif для текста. Подключение через `<link>`, с `font-display: swap` и fallbacks.

## 4. Дизайн-система

**Настроение:** спокойное, тёплое, доверяющее. Много воздуха, без агрессивных цветов.

**Палитра (CSS-переменные в `:root`):**

```css
--color-bg: #FAF6F1;        /* тёплый кремовый фон */
--color-surface: #FFFFFF;   /* карточки */
--color-primary: #7A8B6F;   /* приглушённый шалфейный — кнопки, акценты */
--color-primary-dark: #5F6F56;
--color-accent: #C48A6A;    /* терракота — мелкие акценты */
--color-text: #3B3733;      /* тёплый тёмный текст */
--color-text-muted: #7C756C;
--color-border: #E8E0D8;
```

**Типографика:** заголовки — serif, 2rem–3rem, межстрочный интервал 1.2; основной текст — 1rem–1.125rem, интерлиньяж 1.6–1.7. Максимальная ширина текстовой колонки ~65 символов.

**Вёрстка:** контейнер `max-width: 1100px`, вертикальные отступы секций 80–120px на десктопе. Скругления карточек 12–16px, мягкие тени (`box-shadow` с низкой непрозрачностью, тёплого оттенка).

**Адаптивность:** mobile-first. Брейкпоинты: 480px, 768px, 1024px. На мобильных — одна колонка, уменьшенные заголовки, кнопки на всю ширину.

**Анимации:** минимум — плавное появление секций при скролле (`IntersectionObserver`, `@media (prefers-reduced-motion: reduce)` обязан отключать анимации).

## 5. Секции страницы (строго в этом порядке)

Общая навигация: простой header с именем специалиста слева и якорными ссылками на секции справа; на мобильном — без бургера, ссылки могут переноситься или скрываться, кроме ссылки «Записаться» (якорь на форму).

### 5.1 Hero (`#hero`)
- H1: имя специалиста + специализация («семейный психолог»)
- Подзаголовок: одно предложение о подходе/результате
- CTA-кнопка «Записаться на консультацию» → якорь `#form`
- Фото специалиста (плейсхолдер, см. §7)
- Опционально: 2 коротких факта (опыт лет, формат онлайн/очно)

### 5.2 Польза (`#benefits`)
Карточки (4–6 штук) «С чем можно прийти / что даёт терапия», например: восстановление доверия в паре, детско-родительские конфликты, кризисы отношений, подготовка к разводу или примирение. Каждая карточка: короткий заголовок + 2–3 строки. Подать через «вы» — обращение к посетителю.

### 5.3 Доверие (`#trust`)
- Блок дипломов и образования (список с годами, заглушки)
- Блок принципов работы: конфиденциальность, отсутствие оценок, работа по методу (например, ЭФТ — эмоционально-фокусированная терапия, заглушка)
- Отзывы: 3 карточки-отзыва (заглушки, подписанные инициалами — «М. и Д., вместе 7 лет»). Никаких фейковых фото, только инициалы.

### 5.4 Форма (`#form`)
- Заголовок «Записаться на первую консультацию», короткий поясняющий текст (ответ в течение дня, первая встреча-знакомство)
- Поля: **Имя** (обязательное), **Телефон или Telegram** (обязательное), **Коротко о запросе** (textarea, необязательное)
- Чекбокс согласия на обработку персональных данных (обязательный, предзаполнен)
- Кнопка отправки; во время отправки — disabled + текст «Отправляю…»
- Состояния: успех (зелёное сообщение «Заявка отправлена, я свяжусь с вами …»), ошибка (красное сообщение с предложением написать напрямую в мессенджер — ссылка на Telegram-контакт заглушкой)

### 5.5 Контакты (`#contacts`)
- Футер-страница: город (заглушка), формат работы (очно/онлайн), email, @telegram, телефон (заглушки)
- Простая ссылка «Политика конфиденциальности» (может вести на modal или отдельный скрытый блок на той же странице)
- Копирайт с текущим годом (подставлять через JS)

## 6. Форма → Telegram (бэкенд)

Прямой вызов Telegram Bot API из браузера **запрещён** (токен бота нельзя публиковать). Реализация — Cloudflare Worker (бесплатный тариф покрывает сайт-визитку):

**`server/worker.js`** (~30 строк):
- Принимает `POST` с JSON `{ name, contact, message }`
- Валидирует: `name` и `contact` непустые, строки ≤ 500 символов
- Отправляет сообщение в Telegram Bot API: `https://api.telegram.org/bot<TOKEN>/sendMessage` с `chat_id`, экранируя HTML
- Возвращает `{ ok: true }` или HTTP 400/500 с `{ ok: false }`
- CORS: разрешить `POST` с домена сайта только (не `*` в проде, для разработки допустимо)
- Токен и chat_id — через секреты Cloudflare (`wrangler secret put`), **не в коде**

**Фронтенд (`js/script.js`):**
- Клиентская валидация до отправки (непустые поля, согласие отмечено), подсветка ошибок под полями
- `fetch` POST на URL worker'а (URL — константа в начале файла с комментарием «заменить после деплоя worker'а»)
- Не использовать `alert()` — сообщения об успехе/ошибке рендерить в DOM под формой (aria-live="polite")
- Защита от повторной отправки: disable кнопки до завершения запроса

Инструкция по активации (положить рядом как `server/README.md`): создание бота через @BotFather, получение chat_id, деплой worker'а.

## 7. Изображения

Все изображения — **локальные плейсхолдеры**, которые заказчик заменит. Не использовать стоковые CDN. Допустимо сгенерировать простые SVG-заглушки (абстрактная тёплая композиция, без лиц) или использовать пустые `<div>` с фоновым градиентом и подписью «фото». Формат будущих замен: WebP/JPG, alt-тексты обязательны.

## 8. Нефункциональные требования

- **SEO-база:** `<title>`, meta description (RU), Open Graph теги, семантические теги (`header`, `main`, `section`, `footer`), корректная иерархия заголовков (один H1)
- **Доступность:** контраст AA (≥4.5:1 для текста), `label` у каждого поля формы, видимый `:focus`, навигация с клавиатуры, `lang="ru"`, prefers-reduced-motion
- **Производительность:** общий вес страницы < 300 КБ включая плейсхолдеры; никаких внешних запросов кроме Google Fonts (при желании можно и системные — тогда ноль)
- **Браузеры:** последние версии Chrome, Firefox, Safari, Edge; мобильные Safari/Chrome
- **Аналитика не подключается** в этой версии
